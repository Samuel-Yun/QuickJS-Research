# 本轮设计决定

用户授权：继续制作 PPT Master 版，并“对比一下哪个效果好用哪个ppt”。据此由执行者决定版式和推荐；未伪造任何用户 UI 提交或审批记录。

Stage 1：面向导师和课题组，拿着代码、正式样本与诊断记录解释本周进展，并区分观察与假设。中文，16:9，现场讲述，会后可编辑。沿用白底黑字、6页正文加2页附录，无封面/目录；free_design，无模板工作区。

Stage 2 三个候选（均不增加实验事实）：

1. 代码并排讲解：源码和两引擎指令用共享语义段对齐，下方保留结果与限制；方法对照用大表，诊断页用两列证据。以正常阅读顺序逐步解释，单色细线区分段落。选用此方案：最适合现场指着原指令讨论，保留较宽 V8 指令列。
2. 值流逐步讲解：每页以一条纵向执行顺序串起源码、值与字节码，计时表成为侧栏。白底黑字，细线定位每一步；更适合教学，但本周多组证据会被压窄。
3. 研究记录页：一条边注栏记录证据种类，主体按观察/解释分段，字节码横跨整页。适合会后阅读，但现场两引擎对照需要更多视线移动。

三者均为 custom mode/style，不引用目录基底；如需示意图，候选渲染均为白纸黑线、无纹理、平面无深度的课堂板书，像手册中的可读代码图。不采购/生成图片，本轮 image_usage=none。没有图标。

最终生产：continuous，brief spec，不开 spec-refinement；讲稿 enabled，动画/音频 disabled。原生可编辑表格与文字，flat PowerPoint 结构。字号按1280×720画布：标题36，正文24，段标题26，代码20，注释20，页脚14 px。PPT 使用 Windows 已安装的 Microsoft YaHei/Arial/Consolas；Beamer 的 Fandol 独立保持不变。

比较边界：PPTX 用本机 PowerPoint 实际渲染后检查；Beamer 未有本地 XeLaTeX，不能声称已经视觉验证其 PDF。相同内容并不表示两份页面像素一一对应。
