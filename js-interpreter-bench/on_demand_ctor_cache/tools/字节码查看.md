# 运行后查看字节码

在 `on_demand_ctor_cache` 目录执行：

```bash
# 先用小例子看两版的读取、构造指令
python3 tools/bytecode.py tests/bytecode_demo.js --engine both

# 只看两个函数，输出更短
python3 tools/bytecode.py tests/bytecode_demo.js --engine both --function ownRead --function construct
```

首次使用会自动编译查看用的 qjs，之后复用已有构建。它实际运行原 JS 文件，然后读取运行结束时的 `byte_code_buf`，没有向 JS 源码里追加打印代码，也没有启用会影响 opcode 表的 `DUMP_BYTECODE`。

这个例子的实测输出包含：

```text
A：
000000  get_arg0
000001  get_field                  x
000006  return

按需构造缓存：
000000  v6_get_arg0
000001  get_field_rdi              x  IC[0] delta=6
000006  return
  IC[0] x: 自有字段, offset=0
```

构造调用在 A 中是 `call_constructor 2`，按需版中是 `four_ctor record[0] argc=2`。`record[0]` 是记录编号，实参数量仍然是 2。输出还会显示该记录是否已经学到正计划、是否记住负目标。

## 看自己的程序或基准

```bash
# 构造微基准，只看构造器 C
python3 tools/bytecode.py tests/micro.js --engine both --function C

# 看脚本主体，适合 new 直接写在顶层循环里的程序
python3 tools/bytecode.py tests/micro.js --engine both --function '<script>'

# Octane 单项：先运行，再列出静态函数名和编号
python3 tools/bytecode.py tests/octane/Richards.js --engine method --list-functions
```

运行自己的文件时，将脚本路径替换成自己的 `.js`。`--engine A` 只看原版，`--engine method` 只看按需版，默认是 `method`。函数筛选可以用名称，也可以用列表里的编号，例如 `--function 3`；同名函数会全部列出。

脚本需要命令行参数时，放到最后的 `--args` 后面：

```bash
# 将 my_test.js 和参数替换成自己的文件与输入
python3 tools/bytecode.py my_test.js --engine both --args positive 100 65536
```

查看内置的 `tests/octane/zlib.js` 时会自动带上它需要的读取接口；自己的程序需要预加载文件时，可以用 `--preload 文件.js`，也可加 `--std`。

## 输出保存在哪里

每次在 `bytecode_runs/时间戳/` 新建目录，终端显示完整路径：

已固定保存一份完整的小例子：[原版 A](../docs/bytecode_demo_20261121/A.txt)、[原 SPARSE](../docs/bytecode_demo_20261121/method.txt)、[并排 CSV](../docs/bytecode_demo_20261121/comparison.csv)、[差异](../docs/bytecode_demo_20261121/compare.diff)。输入副本和运行输出在同一目录。它们不是两次失配版的快照。

以后可用 `--output 新目录` 指定保存位置，例如 `--output bytecode_runs/my_dump_01`；不覆盖已有目录。

| 文件 | 内容 |
|---|---|
| `A.txt`、`method.txt` | 经过筛选的可读字节码：offset、opcode、操作数、缓存状态 |
| `A.snapshots.jsonl`、`method.snapshots.jsonl` | 完整静态函数树的运行后快照，含原始指令字节 |
| `compare.diff` | 两版可读字节码的差异，使用 `--engine both` 时生成 |
| `A.stdout`、`method.stdout` | 原程序的输出 |
| `A.stderr`、`method.stderr` | 原程序的报错 |
| `run.json` | 命令、输入哈希、诊断二进制哈希和来源签名 |
| `status.json` | 查看是否完整完成 |

## 范围与实现

目前查看的是**普通同步 JS 脚本主体及其静态嵌套函数树**；包含没有调用过的静态函数。它是运行后的内存快照，不是逐条执行日志。动态 `eval` / `new Function` 创建的另一个函数树、模块和后续异步任务不由这个入口遍历。没有调用过的函数也可能已经在编译阶段准备好了 IC，所以不能把“有 IC 记录”当作“发生过命中”。

查看构建放在 `build/bytecode/`，只增加运行后的快照出口；解释器 opcode handler、准备逻辑和缓存布局保持原样。为了让脚本主体运行后还可读取，查看器临时多保留一份根字节码引用，输出后释放。**性能计时继续使用 `tests/run.py` 的 Release 构建**，不使用这里的运行时间。

每份查看构建保留 `inspection.patch`、`inspection.json` 和 `build.log`。A 取自 `original/`，按需版取自 `modified/` 的冻结源码；不会覆盖 `build/A/qjs` 或 `build/method/qjs`。
