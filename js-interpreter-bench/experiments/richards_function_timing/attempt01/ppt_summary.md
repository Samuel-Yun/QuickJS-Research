# 建议标题：原始Richards整体耗时与原函数批量调用耗时

| 测量对象 | QuickJS median | V8 Ignition median | V8/QJS |
| --- | ---: | ---: | ---: |
| Richards完整Run（ms/Run） | 3.389 | 2.060 | 0.608 [0.603, 0.615] |
| 原函数：左真、右短路（ns/次） | 65.16 | 40.02 | 0.614 [0.606, 0.620] |
| 原函数：左假、右真（ns/次） | 69.10 | 46.75 | 0.677 [0.661, 0.684] |
| 原函数：两侧均假（ns/次） | 68.93 | 45.46 | 0.659 [0.655, 0.669] |

这里的原函数为未经改写的`TaskControlBlock.prototype.isHeldOrSuspended`。

三句结论：

1. 当前同一WSL2平台上，原始Richards整Run的内部批量平均中位数约为QJS 3.39ms、V8 2.06ms。
2. 原函数三条固定状态路径约为QJS 65–69ns、V8 40–47ns/次；这包含循环、方法读取/调用和结果累加，不是self-time。
3. 尚不能用这些微基准计算函数在原Richards中的占比；V8仅有独立诊断的粗采样范围，QJS该项UNAVAILABLE，更不能据此归因总体差距。

必要脚注（正式表）：WSL2 Ubuntu24.04.2/x86_64，QuickJS upstream2026-06-04、GCC13.3 -O2；V8/d8 15.6.21 `--max-opt=0 --no-lazy`。A共同N=256；B各路径共同M=8,388,608。每组每引擎30新进程，合计240/240；每批两次内部单调读钟，含首次调用，无计时前workload预跑。后续重复非全冷态；启动/静态加载在外。方括号为独立进程重采样的比值95%区间。

讲稿补充：QJS/V8的IQR依次为A 0.0872/0.0427ms，B左真1.704/0.837ns、左假右真2.062/1.282ns、两假1.160/1.388ns。完整统计在summary.csv。无删样本或显著性/总体排名声明。
