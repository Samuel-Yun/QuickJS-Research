# Tiers in the pinned JSC revision

For commit `fd3406f133a4e56d7aaf399ba5611ae44b8da7e9`, the built JSCOnly configuration has `ENABLE_JIT=ON`, `ENABLE_C_LOOP=OFF`, `ENABLE_FTL_JIT=ON` (`/home/mzyx/jsc_build_fd3406f/JSCOnly/Release/CMakeCache.txt`). `Source/JavaScriptCore/CMakeLists.txt:313-325` selects the `X86_64` offlineasm LLInt backend for this machine, and `:328-331` selects C_LOOP only under other build conditions. `Source/JavaScriptCore/runtime/ScriptExecutable.cpp:373-424` installs LLInt entrypoints when the option is enabled and no alternative unlinked baseline code is installed.

This revision exposes LLInt, Baseline JIT, DFG JIT and FTL JIT through `Source/JavaScriptCore/runtime/OptionsList.h:84-88,253-256`. It also has conditional OSR and other tier controls. **Do not infer that every JSC invocation must follow one fixed LLInt → Baseline → DFG → FTL sequence.** Which paths actually occur depends on build, runtime options, code shape and heuristics. In this build, the default hot-probe trace showed Baseline and DFG-related compilation/OSR events (`probes/tier/default.stderr.txt`), confirming a useful positive control; it does not prove that every workload reaches FTL.

With `--useJIT=false`, `Source/JavaScriptCore/runtime/Options.cpp:731-752,880-883` disables Baseline, DFG, FTL and RegExp JIT together. `Source/JavaScriptCore/llint/LLIntSlowPaths.cpp:371-378,418-427,481-499` tests `useBaselineJIT` before a successful LLInt→JIT OSR. The LLInt-only hot probe logged entry into OSR *slow paths* but no successful JIT compilation or OSR transition; this difference matters when reading the trace.
