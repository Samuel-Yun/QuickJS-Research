# 四组源码—字节码与调用路径
正式二进制/模式与上轮相同，收集日期不同，不合并样本。原始dump、命令、stdout/stderr和hash均保留。
QJS dump用同revision独立诊断qjs的最终JSFunctionBytecode（DUMP_BYTECODE=1）；不是qjs -d，不是IR。V8 dump来自实际冻结d8。
## 实际改变的因素
|组别|caller表达式|callee与对象|不能视作单独成本的混杂|
|---|---|---|---|
|inline|i+obj.bias|无小callee，own bias|仍有字段读取、循环、两次加法|
|direct_call|stepPlain(obj,i)|全局绑定函数、两个显式参数|全局读取、普通调用、显式对象传递|
|own_method|obj.step(i)|一个参数+receiver，own step|方法读取、this管理、对象shape/feedback|
|prototype_method|obj.step(i)|同一源码，step在深度1原型|多一层查找、对象shape/布局及反馈可能变化|

所有组每目标4096次循环，独立结果8398848；没有方法外提、.call/.bind或正式预热。

## 同一轮的值与实现路径（重点own/prototype）
原型两组的caller/callee最终opcode序列相同（V8跳转注释地址归一化）；对象建立后的路径不同。证据：source_evidence/shared_method_core.json、method_bytecode_equal.json、raw/diagnostics/*_paths.json。
### QuickJS：原型或own方法，i=2，旧sum=7
`get_loc0/get_arg0`使栈为[7,obj]；`get_field2 step`得到[7,obj,fn]，保留receiver；`get_loc1`成为[7,obj,fn,2]。`call_method 1`执行this=obj的stepMethod；返回后栈为[7,5]，add/put_loc0保存12。
callee的push_this/put_loc0将this保存在局部；get_arg0取2，get_loc0/get_field bias取3，add/return返回5。callee是7条/11字节。stepPlain则get_arg1/get_arg0/get_field/add/return，是5条/9字节；没有显式this局部，但普通调用显式多传一个对象参数。
### 源码解释，不当作独立成本测量
全部QJS行号指04be246…未改源：quickjs.c:19107 GET_FIELD_INLINE用find_own_property（6135）在shape hash找atom，没找到时沿shape->proto。keep=1保留receiver并追加复制的函数值；keep=0替换栈中的receiver并释放其引用。data/accessor/exotic路径条件不同。
quickjs.c:18220 call_method取fn/this/argc并进入17746 JS_CallInternal，检查callable/class、栈空间，准备arg_buf/var_buf/stack_buf和frame（17830附近），然后执行callee；返回后释放receiver、fn、参数对应栈引用。18175的call2传JS_UNDEFINED作this，显式argv包含obj和i。
17933的push_this在非strict下检查this tag；本例receiver为object时复制其引用；stepMethod的局部this会初始化并在frame清理时释放。局部/参数读取、bias字段读取也有值复制或释放；quickjs.h:687/707的引用计数仅作用于相应tag，不能把数字当对象计数。
这些说明了额外步骤可能出现在哪里；本轮没有把refcount、frame或lookup分别计时，没有给所有动作单独做动态计数。
### 实测QJS路径
四组均bias own_hit=4096、fallback/helper=0。own_method的step own_hit=4096；prototype_method的step prototype_hit=4096且hops[1]=4096。两组get_field2=4096、selected_entries=4096、selected_direct_call_method=4096；direct_call的stepPlain进入4096次。inline没有额外JS callee（selected_entries=1是目标loop本身）。
计数只来自独立诊断进程，不能替换正式release采样；helper=0不表示查找没有成本。
### Ignition的同一轮
GetNamedProperty a0,step先取得方法，Star3存函数；CallProperty1 r3,a0,r1显式组织fn/receiver/参数，返回值在A。callee直接GetNamedProperty <this>,bias/Add a0/Return，3条/8字节。caller Add r0，再Mov旧sum/Star0保存新sum。虚拟槽位于frame内存，不是CPU物理寄存器。
direct_call改为LdaGlobal stepPlain/Star3/CallUndefinedReceiver2 r3,a0,r1；callee GetNamedProperty a0,bias/Add a1/Return，同样3条/8字节。inline没有额外Call但保留字段读取和两次Add。
实际handler证据复用上轮同hash d8的bytecode/v8_native/GetNamedProperty.disassembly.txt、CallProperty1.disassembly.txt及source_evidence/v8_native_map.json：可见解码、检查、IC/builtin入口、参数准备和间接分发。code creation/机器码存在不等于该分支实际命中；本轮V8精确source/compiler/GN和IC命中率仍UNKNOWN。
