# OPT = NOT_IMPLEMENTED_WITH_REASON

本轮没有到达机制计数/时间门禁，不能从替换多或相同key offset直接选择性能修改。

现在的实际新证据是：目标三个Run读点的receiver来自两个hashed普通own-data布局；key下标都0，right下标2/3；M在它们之间频繁替换。
C机制控制已构建且16/16正确性通过，但独立ON/OFF计数仅保存M.N1，正式计时0/240，C_ON/M桥接UNKNOWN。

因此不实施唯一OPT，也没有改变guard、容量、缓存单位、原型/写/调用/GC/分配器路径。
该结论是**缺少完成机制对照的证据**，不是“证实没有可优化空间”，也不是“证明维护成本无关”。
若恢复可靠执行，先在新修订通过控制门禁、测净策略效果及桥接；之后才决定一个一般规则，并在独立计划中冻结其反证标准与安全测试。不能把定点C_OFF包装成正式OPT。
本轮原定无OPT分支A/M/V8_ON全套1530条也因同一执行阻断未开始，不以旧时间替代。
