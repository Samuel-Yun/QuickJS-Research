# 首次调用计入：A/M/U的三个小案例

270/270有效，30个同轮完整三条件组，见analysis/audit.json。它与mechanism的预建立反馈口径分开，不跨批相除。N由本批内部时间新校准：整数/引用32768，数值65536；每条件两个pilot均>=1秒。

单位ms/完整microRun；每Run包含4096轮目标循环。U/M整数读1.07746 [1.05696,1.08484]，对象引用读1.00843 [1.00205,1.02162]，数值核心1.08766 [1.06190,1.10284]。区间是10000次同轮配对bootstrap探索性95%，未多重校正。

**解释边界：** core M4本身不读目标字段，但本批共用driver在计时内使用`k < config.N`，按源码推导有N+1次支撑性的N字段读取；checksum累加也在计时内。不能称整个M4区间零IC，不能用它精确扣除布局成本。M1/M2的目标字段是每Run4096次，driver仍相同；没有按引擎单改JS。

这与mechanism driver的局部常量N不同，不能把两种模式时间相减。这里的引用案例是对象引用的读取/比较，没有调用读到的函数值；函数值替换/receiver语义另在正确性中覆盖，不冒充函数值计时。

本批不支持“仅把索引缩放移到填充端就能降低稳定读总时间”这一简单假设。实际ELF确认少了property-index左移，但其余生成代码、布局、支撑操作与状态影响没有单独隔离。不能反推shift具有负成本，也不据此说IC没有价值；七条件实验仍支持控制构建内部的条件取值收益。
