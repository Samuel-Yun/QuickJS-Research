# Tree 构造 IC：initial shape 依赖实验

基于提交 7c941da；主基线为冻结 SPARSE。Release 计时与诊断分开；CPU 2、原 Tree 输入与 N=256，原计时边界，首次 Run 计入，无额外热身。所有旧代码和冻结源码不修改，不 push。

## 结论

第一处分歧在构造前查找 initial shape：SPARSE / 旧 P2 / P2_COLD 分别失败 6,605,699 / 3,492,667 / 8,372,555 次；构造后的 initial 缺失、结果布局和分配失败都是零。删除两处硬依赖及 initial 持有后，单槽和冷双槽都达到 512 次发布、10,769,918 次命中。这定位了覆盖下降的直接门槛，没有把更深层的 initial 可见性差异预先归因于槽位布局。

initial 在这里指“相同原型、零个自有字段的空 shape”。QuickJS 可以在首次添加字段时就地扩展不共享的 shape，所以合法构造器不保证一直有一份这样的空 shape 留在全局表中。普通构造找不到它会创建新 shape；原 IC 的学习却直接放弃。命中分配实际使用 final，而不是 initial。这个解释来自源码；各版本为何保留下不同数量空 shape，本轮没有进一步隔离验证。

INIT_FREE 的 Tree 七轮中位数比同批 SPARSE 快 41.78%，稳定单构造器慢 0.23%；P2_COLD_INIT 比父版快 47.33%，稳定用例慢 1.69%。两者 7/7 组 Tree 配对快至少 5%。KEEP_PRIMARY 没有 Tree 收益，不跑全集。P2_SIDE 按条件跳过，因为 INIT_FREE 已恢复冷双槽的覆盖。

## 诊断是否改变路径分布

详细诊断不增加 FourSite、FullPlan、JSFunctionBytecode 字段；使用固定的原生聚合表，不持有 callee 或 shape 引用。对象释放时结束身份代际，避免地址复用被误当成同一个构造器。另跑第二轮轻计数版本比较：

| 版本 | 轻计数 主/副/发布 | 详细计数 主/副/发布 | 是否一致 |
|---|---|---|---|
| SPARSE | 4164533/0/198 | 4164533/0/198 | 是 |
| P2 | 3659741/3617676/346 | 3659741/3617676/346 | 是 |
| P2_COLD | 1219913/1177848/114 | 1219913/1177848/114 | 是 |

没有观察到这两种计数构建之间的路径分布变化。未插桩 Release 本身不提供命中计数，所以不把诊断耗时或上述一致性当作未插桩路径分布的直接测量。
