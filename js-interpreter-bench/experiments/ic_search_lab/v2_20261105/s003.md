# s003 / parent M：整个metadata在首次函数执行时准备

原M编译/读入每个函数就扫描和分配所有site，未被调用的函数也承担该工作；本候选将两处eager调用移到JS_CallInternal的restart入口，read_ic_ready保证只准备一次，并覆盖generator恢复/尾调用入口。
已准备后的opcode、atom所有权、shape准入/引用及M命中/失配路径完全不变；未进入的函数保持普通atom字节码，输出和销毁按原格式处理。首次准备失败时在已建立的frame中按原异常清理，未完成改写前仍是普通code；低内存重试必须验证。
与E的区别是连每site atom+PC metadata都不eager分配，无第8次操作预算、无额外PIC/原型/store；与c008不同，不是按函数长度过滤。可能省未用函数扫描/分配，但新增每次进入的ready分支，并将首次metadata准备计入内部execution区间；不能称frontend完全排除或无成本lazy。
