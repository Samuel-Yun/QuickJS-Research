# 融合原型的值与控制流

## 一次读取中缓存了什么

`walkthrough.js` 的函数是 `function read(o) { return o.value; }`。它对应短参数加载和字段读取这一相邻模式。s001 的缓存记录仍为 shape、字段下标、atom 三项共16字节。d03/d04 复用该记录，不缓存属性值或 property 数组地址。

普通路径先把参数槽持有的对象复制到操作数栈，其对象引用计数增加。字段读取完成当前值的 Dup，随后释放操作数栈上的临时 receiver。shape 失配时仍执行已有正常属性查找和记录维护。

d03 的短参数/局部变量加载先看后一条是否为 `get_field_rdi`。接收者确认为普通非 exotic 对象且当前 shape 与记录一致时，直接从当前 `object->prop[site->prop_offset].u.value` 取得并 Dup 字段值。参数/局部变量槽仍持有 receiver，该段没有分配、用户回调或释放 receiver，所以可省掉那对临时 Dup/Free，并一次跳过后续字段 dispatch。返回值本身需要的引用保留。失配则恢复原加载流程。

d04 在准备时给相邻加载改为专用 opcode，仅让符合模式的位置尝试上述路径。第二条字段 opcode 的物理位置和字节保持，它仍可成为独立跳转入口。两种版本的取舍是动态 lookahead 覆盖成本、额外 handler 与机器码布局，不能仅凭源码判断哪一个总体更快。

## 两个布局和一次换值

先建立 `a={value:10}`、`b={pad:0,value:20}`，二者字段位置不同。

1. 首次 `read(a)` 的记录尚空。进入正常字段路径，取得10并记录 a 的 shape 和下标。
2. 第二次 `read(a)` 在匹配时可走融合读取，返回10。
3. `a.value=11` 沿用普通数据属性布局，下一次仍加载当前值11。记录中没有保存10。
4. 首次 `read(b)` 与 a 的 shape 失配，回到正常加载/查找，取得20并记录 b 的真实下标。
5. 第二次 `read(b)` 可以用该新下标走融合读取。最终序列必须为 `10,10,11,20,20`。

这是控制流说明。是否实际执行了融合分支，需看独立诊断的计数。它也没有给出该分支的独立 self-time。

## 语义范围

getter、Proxy、primitive、异常、unhashed/不匹配 shape 都沿原路径。融合只处理已缓存的 own 普通数据字段，方法读取 `get_field2_rdi` 保留原语义。全局、闭包读取和非短编码局部变量也没有被这一原型融合。

静态字节码位置不缩短。减少一次 dispatch、避免一对临时引用操作和整段程序变快是三种不同的陈述。前两项可由路径与窄诊断核对，时间结论需依据独立样本。机器码布局对数值控制的影响仍需另列。
