# 本次有限复检与恢复规则

原 protocol.json、STOP.json 和初始批次不改写。最初预检使用沿用的 UTC/外层
MONOTONIC 差异不超过 1 秒的规则，第一次通过；正式首轮在第 74 个进程触发该规则。

第二次、也是本环境最后一次预检增加只读的独立时钟交叉核对。这不是简单提高阈值：
UTC 的 0.803 秒跳变本身不足以证明 MONOTONIC 错误，但本次还实际观察到：

- 30 次 sleep(1) 区间：MONOTONIC 30.465540732 秒，RAW 29.696671702 秒。
- 包含两次实际 zlib 负载的 Linux 区间：MONOTONIC 47.068939383 秒，RAW
  46.121214820 秒。
- 包住整个 WSL 命令的 Windows Stopwatch 仅 46.6387301 秒；Windows UTC
  同时为 46.6420233 秒。Linux 内层 MONOTONIC 超出外层 0.430209283 秒。

证据见 precheck.2.raw.json / precheck.2.host.json。RAW 不是自动正确的替代品，
也未将既有二进制/适配器偷偷换成 RAW。本次不能确认目标量级的计时可靠性。
本环境不进行第三次性能重试，不继续扩展计数工程；全部初始批次隔离。

恢复只允许在用户自行恢复环境、产生新 boot 后进行，使用独立 epoch、完整重新
采集 A/s001/P1。旧 73 条 measurement 不补齐成新批次，不跨 boot 合并。
恢复入口增加 RAW/选定 MONOTONIC 的只读交叉检查：30 秒预检漂移不超过 50ms，
逐进程差异不超过 5ms + 外层单调区间的 0.2%；保留原有 UTC 门槛。该新门槛
仅供将来新批次，不追溯宣布旧样本有效。它也不保证主机负载、温度等完全受控。
