# v6_get_arg0 实际机器码对照

读取已测量的两个 Release 二进制，没有重新编译，也没有增加计时。
用 nm 定位 dispatch_table.86，再从 ELF 中读取 opcode 0xf7 的 handler 地址；两版入口都是 0x291be。

原 SPARSE 的对象分支在 0x2cf70：0x2cf93 比较 shape，0x2cf96 用 jne 跳到失配路径；命中时顺序进入 0x2cf9c 的取槽代码。

改版对象分支在 0x2d0c5：0x2d0ea 比较 shape，0x2d0ed 用 je 跳到 0x3052c 的取槽代码；失配时顺序进入压栈、转共用查找入口的代码。

因此，命中路径虽然保留原 C 取值逻辑，实际机器码的分支方向和基本块位置已经变化。寄存器分配也不同。
这能证实代码布局发生变化，不能单靠这份反汇编证明它造成了已测到的某个百分比退化；仍需同批计时和进一步对照才能归因。

两个 .asm.txt 文件保留对应真实指令；metadata.json 保存二进制哈希和 objdump 命令。
