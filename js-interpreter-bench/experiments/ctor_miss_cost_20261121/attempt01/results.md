# 构造 IC 零命中成本：正常组与直接普通构造组

结论来自同一批次未插桩 Release。两组都以冻结 SPARSE_CTOR_IC 为底座；BYPASS 只替换 OP_four_ctor 的 handler，仍保留构造位点准备/记录、属性读取 IC、读取融合、读写共享记录、冷准备和 C 的 shape 转换缓存。没有修改缓存策略或运行全集。

## 两组耗时

| 条件 | 5 次独立进程耗时（秒） | 中位数（秒） | 最小～最大（秒） |
|---|---|---:|---:|
| 正常构造 IC | 10.4128 / 10.4643 / 10.4339 / 10.4647 / 10.4063 | 10.4339 | 10.4063～10.4647 |
| four_ctor 直接普通构造 | 6.7404 / 6.7513 / 7.0212 / 6.9364 / 6.7344 | 6.7513 | 6.7344～7.0212 |

正常组比直接普通构造组慢 **54.55%**，总计多 **3.6826 秒**；换成旁路组，相对正常组少用 **35.30%** 时间。每次循环平均多约 54.88 ns；这是两组整段循环差值除以 N，不是逐函数计时。

## 输入和计时边界

逐字节复用 sparse_whitebox_20261116/attempt01/ctor.js，命令参数均为 `positive 0 67108864`。原脚本将两个构造函数命名为 A/B，对应本次所说的 C/D；两者都是 `function(x,a){this.x=x;this.a=a;}`，身份不同，共享原型、字段布局及实参。没有为了重命名而改 JS。长度 65,536 的预生成序列严格交替，唯一工作位点是 `ctorLoop` 的 `obj=new C(3,0)`。原脚本的 `new Array(length)` 位于 Setup，不算工作位点。

N=67,108,864，每进程校验和=201,326,592；生成序列和结果校验在计时区间外。performance.now 计时整段 ctorLoop，无额外预热，首次调用计入；每组 5 个新进程，顺序 NORMAL/BYPASS、BYPASS/NORMAL 逐轮交换。CPU 2、Asia/Shanghai、LC_ALL/LANG=C。计时期间不编译、不并行运行其它测试。

## 正常组实际命中情况（独立计数进程）

- 目标静态位点：ctorLoop，pc=18，argc=2，共一个位点。
- 查询 67,108,864；正命中 0；实际正命中率 **0.00000000%**。
- 普通构造 67,108,864 次；负缓存命中 0 次。
- 尚无计划 2 次；已有计划但构造目标不同 67,108,862 次。
- 成功学习/更新计划 67,108,863 次。

COUNTS 不定义 FOUR_DIAG，不增加每点字段/日志指针，不改 FourSite/FullPlan、缓存策略或学习条件。通过 CTOR_PROBE_FUNCTION=ctorLoop 选择诊断范围，所有计数在这个位点内进行；计数版使用同一份 JS 和相同参数，时间不进入上表。

## 没命中后，正常组多执行了什么

| 工作 | 普通构造前的资格检查 | 普通构造后的学习 | 首次负记录检查 | 合计 |
|---|---:|---:|---:|---:|
| 模板解析入口 | 67,108,863 | 67,108,863 | 1 | 134,217,727 |
| 调用/类别/参数/栈/GC 条件检查 | 67,108,864 | 0 | 0 | 67,108,864 |
| 构造函数 prototype 数据属性查询 | 67,108,863 | 67,108,863 | 0 | 134,217,726 |
| 字段原型链资格检查 | 67,108,863 | 67,108,863 | 0 | 134,217,726 |
| 上述检查中的属性描述符查询 | 268,435,452 | 268,435,452 | 0 | 536,870,904 |
| 空 shape 查询 | 67,108,863 | 67,108,863 | 0 | 134,217,726 |

完整路径是：先尝试当前计划（本例大多在目标身份比较处失败），再查负缓存，做可学习性检查，然后仍执行普通构造；成功后再次解析模板、核对原型/布局/字段描述，更新 callee、shape 引用和 recipe。直接普通构造组跳过这些 IC 尝试、判型、学习与更新，保留参数/返回值所有权、原异常路径和栈清理。

其中 67,108,862 次更新的 initial shape、67,108,862 次更新的 final shape 与原记录相同，原代码仍执行对应的引用更新。完整计划本身按需分配后复用；不能把每次计划更新说成每次都分配新的 FullPlan。

两种构造目标本身都符合模板，负缓存帮不上这个交替输入；单槽计划反复换成当前目标，下一次又换成另一个目标，导致零命中仍反复学习。这次只测这份代价，没有据此修改策略，也不能把整段差值全部归到某一个解析函数。

## 文件和复现

`BYPASS.patch` 是相对冻结 SPARSE 的唯一 Release 改动；`NORMAL.patch` 为空。`COUNTS.patch`、probe.inc/probe_site.inc 保存独立计数改动。manifest 保存每份源码和二进制哈希；raw/ 保留所有进程输出、时序和环境。analysis/samples.csv 为 10 个原始时间，summary.csv 为中位数/范围，work_counts.csv 为按阶段拆分的计数。复现命令见 REPRODUCE.md。
