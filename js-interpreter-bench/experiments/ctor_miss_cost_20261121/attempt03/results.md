# 连续两次身份失配后再学习

从原 SPARSE 独立派生 TWICE：先执行原四构造缓存尝试。只有失败且已有正计划、构造器身份不同时，增加连续失配计数（饱和到 2）。第一次只普通构造，第二次起允许走原资格检查/学习；成功学习后清零。命中或同目标的其它检查失败会打断连续身份失配，计数非零才清零。

计数器占原 FourSite 尾部 padding 的 1 字节（offset 30），记录仍 32 B，FullPlan 仍 96 B，没有加槽、待学习目标引用、额外分配或新 opcode。原 plan_try 的检查与构造体不改。

## 验证与范围

gate 对照 setter、只读字段、原型替换、目标切换、异常和非法构造目标；policy_probe 额外验证：一次身份失配后，同一构造器因 setter 检查失败，会清掉连续失配计数并走原普通构造。随后 D 的第一次身份失配仍须等待，第二次才学习，下一次命中。输出与两个对照一致。

三份输入及总 N=67,108,864、每段 N/2、CPU 2、上海时区、C locale、首次 Run 计入、无额外预热等均沿用前轮。两个对照复用已验证的 Release 二进制，45 个时间全部本轮新进程，没有沿用旧时间。9 个计数进程独立运行。所有样本包括慢点均保留，不自动增加轮数。

TWICE.release.patch 相对原 SPARSE，只改 quickjs.c 和 four_runtime.inc。analysis/samples.csv 是 45 个时间；summary.csv 为主表；switch_phases.csv 为分段时间；switch_trace.csv 为 D 前 8 次调用轨迹；counts.csv 为工作量及状态写入计数。原始输出在 raw/，复现见 REPRODUCE.md。
