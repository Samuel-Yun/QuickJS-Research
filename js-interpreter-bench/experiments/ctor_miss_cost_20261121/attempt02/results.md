# 保留旧正计划：交替、稳定与换目标

本轮只增加 KEEP_PLAN：已有完整正计划且当前构造器身份不同时，跳过缓存尝试、模板解析和学习，直接调用原普通构造；不释放或覆盖旧计划。身份相同时继续执行原快路检查、回退与学习。FourSite/FullPlan、prepare/opcode 表示、所有权、GC 和其它优化不变。

## 计数解释

交替输入的旧脚本中，两个目标名称为 A/B，对应本次 C/D，JS 未为重命名而改动。正常组零命中且反复更新；新版只保留第一次成功学到的目标，另一个目标直接普通构造，因此约一半调用命中。这个输入里最早成功学到的是 D：C 首次调用后未学习，D 随后学到计划；这不是按名字选择 D。

全 C 下两版正命中覆盖与更新次数相同。时间差仍按上表原样保留，不能仅凭覆盖相同就说性能没有变化。先 C 后 D 的新脚本在计时外准备两个数组，先全部 C、再全部 D；不是在长度 65,536 的环形序列里重复交替两大块。ctorLoop 函数体逐字节复用旧脚本，没有在热循环里增加阶段分支。

新版在交替输入下的变化同时包含“减少重学”和“恢复约一半正命中”，不能把全部加速只归于失配检查减少。当输入从一种稳定构造器转为另一种时，固定保留旧计划会失去新阶段本来可以获得的正命中收益。

## 实验条件与交付

所有输入总 N=67,108,864，校验和=201,326,592；序列生成与验证在计时外，无额外预热，首个调用计入。CPU 2、Asia/Shanghai、LC_ALL/LANG=C。NORMAL/BYPASS 复用前轮已核对的 Release 二进制，但本轮 45 个时间都是同批次新进程，没有沿用前轮时间。不同版本顺序按轮次轮换。

计数在 9 个独立进程中运行，不定义 FOUR_DIAG，不增加每点字段或缓存记录尺寸；不把计数版时间放进表格。phase_C/phase_D 按实际目标对象身份区分，两目标在脚本中持续保活。身份不同时的直接路径使用 identity_bypasses 单列，不冒充正命中。Release 没有这些计数。

`KEEP_PLAN.release.patch` 相对冻结 SPARSE，仅修改 quickjs.c 的 OP_four_ctor。analysis/samples.csv 保存 45 个时间，summary.csv 是主表，switch_phases.csv 是分段表，counts.csv 是计数表；raw/ 保留命令、环境、进程起止和原始输出。复现见 REPRODUCE.md。
