# 选择依据与已验证机制

本批性能版本不包含诊断计数。以下诊断和性能采样串行，原始资料在[attempt02/diagnostics](../attempt02/diagnostics/)，选择在新候选性能采样前冻结。

这些是独立父版轨迹中的机会数，不是原生耗时占比，也没有把它们冒充新候选实测省下的指令数。

对同样的原N=1区间，Callgrind使用VM源码逐字不变、只增加边界控制hook的另一个父版镜像。Boyer普通调用清理循环对应源码行的self Ir为11712917，总Ir为1142069720，约1.03%；RayTrace方法调用清理循环为1683813/400536478，约0.42%；Richards为156147/31605844，约0.49%。这里只是对应源码行的指令归属；JS_FreeValue的内联与调用成本分布在其他行，循环也并非全部可删除，不能作为CPU耗时或可实现收益上限的精确估计。

三个候选的独立ASan/UBSan机制探针都通过：

- COALLOC：七个fixture验证源码编译函数标记、记录地址与8B对齐、24B记录及144B函数头。与冻结父版逐条比较opcode、非IC操作数、atom和site顺序；PC相对距离允许因整体放置位置改变。验证热字节码写出、加载的外部分配回退，以及八次编译函数目标分配失败注入后的异常清理和恢复。六个含IC的fixture分别避免一笔外部分配及7/9/48/18/7/20字节的额外代码复制；无IC fixture不增加记录存储。
- FUSE_A1L1：原B2与P1原型命中继续发生；新arg1与loc1融合各实测31次命中。第二条属性指令独立入口、普通失配以及保存加载由共享回归覆盖。
- CALL02：原B2/P1继续命中，0/1/2参数的展开路径分别实测68/3/2次；另一个独立原生finalizer测试验证普通和方法调用0～5参数的释放顺序，共36次finalizer。

这些是专项机制与安全验证，不等于完整test262、泄漏验证或生产验收。LSan关闭。COALLOC的加载路径仍是旧存储方式，本轮没有宣称已经消除所有来源字节码的二次分配。没有额外测量峰值内存；过程记录中的wait4 peak_rss不作为VM内存收益，因为它可能包含exec前子进程继承的父进程峰值。
