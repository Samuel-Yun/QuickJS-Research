# P1+B2 后续两项改动：五轮探索结果

两项改动已分别实现、完成安全检查和五轮Octane。PREP2有小幅正向点估计，但增量区间跨零；SPLIT16出现整体回退。本轮没有取得明确超过5%的改善，也没有把两者组合或追加轮数。

负数表示耗时降低；各case先取五次中位数，再按原suite等权几何聚合。核心集合为16项/13suite，扩展集合包含zlib，为17项/14suite。

|版本|改动|核心相对P1+B2|核心相对A|扩展相对P1+B2|扩展相对A|
|---|---|---:|---:|---:|---:|
|冻结P1+B2|已有父版，复用旧数据|—|-4.37%|—|-4.36%|
|PREP2|把B2融合标记并入opcode改写扫描，三遍变两遍|-0.44%|-4.79%|-0.45%|-4.79%|
|SPLIT16|普通读记录16B，保留receiver的记录24B|+0.77%|-3.64%|+0.71%|-3.69%|

PREP2核心相对父版耗时变化的95%探索区间为[-0.89%, +0.13%]，尚不能确认这0.44%为稳定增量。SPLIT16为[+0.29%, +1.17%]。这些区间来自独立新旧整轮bootstrap，不覆盖跨批次系统漂移。两个新版本在本批交错采集，SPLIT16相对PREP2核心慢1.22%，配对整轮bootstrap区间为[+0.62%, +1.56%]；这也不支持继续叠加布局版。

PREP2的CodeLoad.Closure/JQuery相对父版分别降低1.81%/1.28%，方向符合减少准备扫描的假设，但仍比A慢8.10%/5.00%左右；仅凭总时间不能把所有变化归因到准备扫描。DeltaBlue、RayTrace、Splay分别降低1.50%、1.03%、1.20%，Richards反而增加0.41%。SPLIT16的RayTrace增加7.40%、Richards增加3.29%；Splay降低1.85%，没有抵消其它回退。完整17项的中位数及变化见[results.md](results.md)。

布局探针确认普通记录16B、方法记录24B，JSFunctionBytecode头仍为144B；每个有IC的函数新增8B布局头。因此只含少量普通读或只含方法记录的函数可能没有净空间收益。探针中的两条普通记录由48B降至40B，单条方法记录则由24B增至32B。当前没有采集整个Octane的峰值内存，也没有完成RayTrace回退的成本归因，不能把该回退直接解释为布局头的成本。

共170条新性能样本（17项×2版×5进程）和34条Octane正确性记录，全部通过；未重跑A、P1+B2或V8_ON，也没有运行SunSpider、V8_OFF。所有计时进程固定CPU2、串行执行，单条有效计时均不少于1秒。PREP2逐项CV中位数0.28%、最大1.54%；SPLIT16为0.49%、最大2.18%。这些波动不包含旧对照的批次漂移。

两版均通过针对性JS、C API保存加载、GC、原生finalizer和qjsc检查，以及ASan/UBSan专项检查。LSan因前一批已确认的环境限制关闭，未声称完整test262通过。独立探针实测B2融合与P1原型命中；PREP2还对五个fixture与冻结父版准备结果逐字比较通过。性能二进制没有开启诊断计数。

源码、输入、运行时哈希及调度审计为PASS_COMPLETE，独立原始数据统计复算为PASS。生成器见[variants.py](variants.py)，可审阅补丁见[PREP2](patches/PREP2.from_P1_B2.patch)及[SPLIT16](patches/SPLIT16.from_P1_B2.patch)，完整原始过程保存在[raw/runs.jsonl.gz](raw/runs.jsonl.gz)。旧实验数据保持原样。

PREP2保留为待最终同批确认的小幅候选；SPLIT16保留负结果，不提升为底座。后续应先对冻结P1+B2的CodeLoad、EarleyBoyer和RayTrace做成本归因，再选择新的执行路径改动。已有小幅改善不足以支持继续盲目压缩记录或扩大融合组合。
